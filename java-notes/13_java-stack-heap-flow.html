Java Stack & Heap Memory — Simple Explanation

Java memory ko do main parts me divide kiya jata hai: Stack aur Heap.

  • Stack — method calls aur unke local variables/references yaha store hote hain. Method khatam hote hi ye clean ho jata hai.
  • Heap — new keyword se banaye gaye actual objects yaha store hote hain. Ye tab tak rehta hai jab tak koi reference use point kar raha ho.

Example Code

class Calculator {
    int num;        // default 0
    int num2 = 5;

    public int add(int a, int b) {
        return a + b;
    }
}

public class Methods {
    public static void main(String[] args) {

        int data = 12;
        Calculator calc = new Calculator();
        Calculator calc2 = new Calculator();

        int sum = calc.add(5, 10);
        System.out.println("Sum: " + sum);

        calc.num = 10;

        System.out.println(calc.num);   // 10
        System.out.println(calc2.num);  // 0
    }
}

Diagram

calc (value 101) → connects to the object at Address 101. calc2 (value 105) → connects to the object at Address 105. Each reference points to its own exact object — not the other one.

Note: 101, 105 jaise addresses sirf samajhne ke liye (for understanding only) diye gaye hain. Real JVM me actual memory address kabhi print/access nahi hota — ye ek simplified representation hai.

Is line ke liye:

int sum = calc.add(5, 10);
System.out.println("Sum: " + sum);

1) calc (stack me 101 address) heap ke 0x101 object ko point karta hai, isliye calc.add(...) wahi object ka method call karta hai.
2) Call hote hi ek naya add() stack frame banta hai (upar table me) — usme sirf a = 5, b = 10 store hote hain, kyunki ye method ke local parameters hain.
3) return a + b chalte hi result 15 caller ko milta hai, add() frame turant stack se hat jata hai (pop), aur wo value main() frame ke sum variable me store ho jati hai (jaisa upar table me dikh raha hai).
4) Fir System.out.println stack ke sum ki value read karke print karta hai.

How It Works

StepWhat happens
1new Calculator() runs twice → two separate objects created on Heap
2calc and calc2 (on Stack) store only the address of their own object
3calc.num = 10 changes only the object at 0x101
4calc2's object at 0x105 stays untouched → its num is still 0

Key point: Each object gets its own copy of instance variables (num, num2) on the heap. The stack only holds references (addresses) pointing to them.
